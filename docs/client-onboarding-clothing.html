Shopkeeper's Guide - Clothing Billing with Barcode Scanning

1. What you need (one-time)

Meet Ramesh, who owns Fashion Point, a shirt-jeans-t-shirt shop. His dealer installed the billing app on the shop computer. This is all the shop needed:

Thing What exactly Why
Computer Windows 10 or 11, 64-bit, 4 GB memory, 2 GB free disk Runs the till + its own database. No server, no internet needed after setup.
Barcode scanner Any USB "1D" scanner, about Rs. 1,500. Must be keyboard mode (HID) - the default on cheap scanners. Scans price tags. It behaves like a very fast typist.
Printers (two jobs) An A4/sticker printer for price-tag stickers; an 80 mm thermal printer (USB) for customer bills. Tags for garments, bills for customers. Two different printers, set once in Hardware Manager.
Muftgo key A secret the Muftgo team types on the shop computer once, never given to staff in writing. Without it the app never opens - so a copied installer is useless to anyone else.
Internet? Only needed once, during installation. After that the shop runs fully offline. Billing never stops because the Wi-Fi did.

2. First start: Muftgo activation key

  1. Double-click the billing app. The first screen says Activate MuftGo Billing.
  2. Call the Muftgo team. They type the team key on this computer once and press Activate.
  3. Done - once per computer, forever. The login page appears. Shop staff never see or handle this key.
Real life: Ramesh's nephew copies the app to his home laptop "to practise". It opens on the activation screen and stops there - only the Muftgo team has the key. The shop's data never leaves the shop.
New computer? Shifting to a new PC? Install there and call the Muftgo team once - they activate the new PC. The old PC keeps working. If the key is ever leaked, the Muftgo team rebuilds the installer with a fresh key.

3. How scanning works: USB gun, camera, phone

Three ways a tag reaches the bill. All three land in the same place - the sale screen's Find item name, sku or barcode box - so they can never disagree.

Method How When to use
USB scanner gun (main) Plug into USB, point 10-15 cm at the tag, press the button. It types the number + Enter by itself. Everyday billing. Fastest: beep-beep-beep, one beep per piece.
Camera button (backup) On the sale screen press the camera icon, point the till webcam at the tag. Works offline (Chrome/Edge or the app window) - reads the barcode or the QR. Gun battery dead, gun forgotten at home, one tag torn and faint.
Type the number (backup) Type the 6-digit number printed under the barcode, press Enter. Tag too damaged to scan at all.
And the phone? Every price tag carries two codes with the same number: a barcode (for the Rs. 1,500 gun) and a QR (for any phone camera). So a phone CAN read any tag - open the phone camera, point, see the number. But the phone does not push the scan into the till screen by itself. The supported phone paths are: (1) a phone app that acts as a Bluetooth scanner (the till sees it as a keyboard, same as the gun), or (2) handset ordering where given. For counter billing, keep the USB gun in hand - it is ten times faster than any camera.
Gun test (30 seconds, do once): open Notepad, scan any tag. The number must appear AND the cursor must jump to the next line. If the cursor stays on the same line, the gun's "Enter suffix" is off - turn it on from the gun's manual (it is called "suffix" or "terminator"). Without it, scans pile up in the box and nothing lands on the bill.

4. Shirts, jeans, t-shirts: one barcode per size

A shirt is not one product - it is one design in many sizes. The app keeps each size as its own item with its own barcode, so scanning an XL can never deduct an M from stock.

Ramesh's shelf looks like this - 3 designs, 12 size-items, 12 barcodes:

Design (one family) Sizes = items Barcodes (auto-given)
Men Formal Shirt - Blue Checks M, L, XL, XXL (4 items) 200031, 200032, 200033, 200034
Slim Jeans - Dark Blue 28, 30, 32, 34 (4 items) 200035, 200036, 200037, 200038
Round-Neck T-shirt - Black S, M, L, XL (4 items) 200039, 200040, 200041, 200042
Golden rule of garments: one barcode per size per colour. "Blue shirt" is not a product - "Blue shirt, XL" is. If two piles share one barcode, the computer cannot tell which pile sold.

To make a family: Add > Item, name the design, tick This item has variants, option Size with values (e.g. M, L, XL, XXL), Save. The app makes one item per size, each with its own barcode number. Same for jeans (28, 30, 32, 34) and t-shirts (S, M, L, XL) - and repeat per colour: "Black" and "White" of one t-shirt are two families.

5. Morning delivery: purchase entry + bulk barcodes

9:30 am. Ravi Textiles delivers against bill RT-1042: 20 formal shirts (M-8, L-7, XL-5), 15 jeans (28-4, 30-5, 32-4, 34-2), 24 black t-shirts (S-6, M-8, L-6, XL-4). Priya at the counter does this - total about 15 minutes:

  1. Open Purchase (left menu) > New Purchase. Choose supplier Ravi Textiles, type bill number RT-1042.
  2. Click the Find item box and type shirt. Every size appears as its own line - Shirt / M, Shirt / L, Shirt / XL… There is no separate "variants" box here: sizes ARE items. Add each line and set its quantity (M-8, L-7, XL-5) and cost price from the bill. Same for jeans sizes and t-shirt sizes.
  3. New design not in the list? The search shows a create row for the typed name - or click Add > Item, type name (e.g. Men Linen Shirt - Green), price, MRP, quantity, ticking This item has variants with Size values if it has sizes. Leave the barcode box empty. The app gives it the next free number itself (…200043, 200044…). Save, then add it to the purchase.
  4. Press Save. Stock is now in the computer, size by size.
Bulk, no typing: leaving barcodes blank across 40 new size-items gives 40 fresh numbers in one save - next-free after the highest in use, skipping anything already taken, never giving one number twice. That is the whole "bulk barcode generation": blank means "next free number, please".

6. Bulk sticker printing on A4 + tagging

The 59 pieces need 59 stickers before lunch. Fastest way - one button for the whole delivery:

  1. On the purchase screen, with all lines and quantities entered, press Print stickers (bottom bar, next to Save).
  2. The app prints one sticker per piece automatically - M-8 stickers, L-7, XL-5, jeans 28-4… each size carrying its own barcode - tiled on A4 sheets. Works before Saving too, so stickers print while the supplier waits.
  3. Lines with no barcode yet are skipped and counted on screen ("2 line(s) had no barcode") - save those items with their barcodes, then print again.

Single-size top-up (7 more L stickers later): open Items, click the size-item, press Barcode labels, set Number of stickers = 7, Print. One sticker = single label; more = full A4 sheet. (Ordering through Purchase Orders instead? Open the order > Print labels does the same per ordered quantity.)

Every sticker shows shop name, price, MRP, the barcode and the QR - both carry the same number. Print to the sticker/A4 printer - never a PDF or XPS writer.

Tagging: stick one label per piece: inside collar (shirts/t-shirts), inside waistband (jeans), saree fall edge - same spot every time, so hands find it blind at sale.
Counting right: 59 pieces = 59 scans at tagging time is wrong thinking - tagging prints per size (7 copies of L, 8 of M…). At SALE time, scan each piece: 5 identical socks = 5 scans, not "scan once, type 5". The stock stays honest only if every piece beeps.

7. Selling: scan, bill, remove the sticker

6 pm rush. A customer brings 3 shirts and 1 jeans to the counter.

  1. Open New Sale (left menu > Home > New Sale). Click the Find item name, sku or barcode box once.
  2. Hold each garment's tag 10-15 cm under the scanner and press its button - beep, next. Four beeps, four lines on the bill. Each beep also reduces stock by one.
  3. No gun in hand? Type the 6-digit number + Enter, or press the camera icon and point the webcam at the tag.
  4. Take cash/UPI, press Charge / Save, hand the printed bill.
  5. Peel the price sticker off and hand over the garment. The sticker has done its job - the sale is in the computer now. (Keep a small bin at the counter for peeled stickers; never stick a peeled sticker on another piece.)

8. Next batch: how new numbers are born

Next week Ravi Textiles sends a new design: Men Casual Shirt - Red Stripes (M, L, XL). Priya clicks Add > Item with variants, leaves barcodes blank, saves. The app continues above the highest number in use (…200043, 200044, 200045) - it never reuses an old number and never fills gaps left by deleted items.

Never reuse a barcode number for a new design, and never type 200001-style numbers as quick-sale shortcut codes. Old tags live on in old wardrobes; a recycled number sells yesterday's shirt today. New batch = blank boxes = fresh numbers, always.

9. Bills and printers: thermal over USB + those .prn files

Those Receipt #S-BWJQ-000015.prn files (1 KB) are NOT printed bills. A .prn file is the raw printer data saved to disk instead of paper - the bill went to a file-writer, not to the thermal printer. Nothing reached paper.

Why it happens: the bill was sent to a virtual printer (Microsoft Print to PDF, XPS Document Writer, OneNote, Fax) or "Print to file" was ticked, or the Windows default is a virtual printer and the app fell back to it. The save dialog then defaults to OneDrive Documents, hangs, and errors - which is exactly the symptom this build guards against.

Yes - with the USB thermal connected properly, printing succeeds silently: no dialog, no file, paper comes out. Checklist, once:
  1. Connect the 80 mm thermal via USB, install the vendor's driver, print a Windows test page.
  2. In the app open Hardware Manager: Receipt Printer = your thermal (80/58mm), Report Printer = your A4 printer.
  3. In Windows Settings, do NOT leave Print to PDF / XPS / Fax as the default - make the thermal the default.
  4. Untick Print to file anywhere you see it.
  5. Reprint the stuck bills from Sales History - they will now come on paper. Delete the old .prn files; they were never bills.

10. Size exchange and return - no sticker needed

Next day the customer returns: the L shirt is tight, he wants XL. The price sticker was peeled off at sale and thrown away - that is correct, and no rescan is needed. The return works from the bill, not from the tag:

  1. Open Sales History, find yesterday's bill (by bill number, date, or customer phone).
  2. Open it with the Return action. Every line of that bill loads on screen - L shirt, jeans, everything.
  3. Set the return quantity on the L shirt line (stock goes back up by one), then add the XL shirt as a new sale line - scan a fresh XL tag from the shelf, or pick it by name (stock goes down by one).
  4. If XL costs more, collect the difference; if less, refund it. The bill shows both lines, so the accounts stay honest.
Thrown sticker? Never a problem. Only the exchange item coming FROM the shelf needs its tag scanned. The item going BACK needs only its bill line.

11. Evening: day close in 5 minutes

  1. Sales History - today's total, bill count. Match cash in drawer + UPI credits.
  2. Items > low stock - anything at zero (e.g. Jeans-32 sold out) goes on tomorrow's order list to Ravi Textiles.
  3. Close the app. The computer can switch off - everything is stored inside it, with automatic backups if enabled.

12. When something goes wrong

Symptom Fix (try in order)
Pressing Print saves a .prn file instead of paper Not a success - see §9. Set the thermal as Receipt Printer in Hardware Manager, take PDF/XPS off Windows-default, untick Print-to-file, reprint from Sales History.
Print dialog opens, loads OneDrive, then errors A virtual printer (PDF/XPS/OneNote/Fax) is the default. Same fix as §9.
Scanner types numbers but item never lands on the bill 1. Scan into Notepad - if the cursor stays on the same line, enable the Enter suffix in the scanner manual. 2. Click the sale's item box once (the scan goes wherever the cursor is).
No camera icon on the sale screen Open the shop in Chrome or Edge while the app runs. Firefox/Safari cannot camera-scan - use the USB scanner there.
Scanning adds the WRONG item Two products share one number. Open each, give one a fresh number (or leave blank and save - auto-numbering picks a free one), reprint its tags.
App asks for the Muftgo key again The data moved to a different computer (or Windows was reinstalled). Call the Muftgo team once - normal and expected.
App shows blank / database won't start on a brand-new PC Install Microsoft Visual C++ Redistributable (x64) from microsoft.com, then start the app again.
Forgotten shop login Call the dealer - they reset the cashier login on the shop PC in a minute. The Muftgo activation key is separate and stays with the Muftgo team.

13. Three things you must never do

  1. Never ask for or keep the Muftgo key - it belongs to the Muftgo team, not the shop. Cashiers get their own login (Users menu).
  2. Never reuse a barcode number for a new design, and never type 200001-style numbers as quick-sale shortcut codes. Old tags live on in old wardrobes; a recycled number sells yesterday's shirt today.
  3. Never delete a product that has sales. Out-of-fashion? Set its stock to zero and stop ordering it. History must keep pointing at it.
